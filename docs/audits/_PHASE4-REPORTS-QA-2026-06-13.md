## /reports/pnl
- **[HIGH/null-cost/certain] COGS not reduced by returned-goods cost → gross/net profit understated whenever there are returns**
  - evidence: apps/api/src/modules/report/pnl.service.ts:87-90 (returnRows query) selects `SUM(sum_minor) ... NULL::bigint AS cost_minor FROM sales_returns`. computeTotals lines 107-114: `const sales=sumRevenue(demandRows); const cogs = demandRows.reduce((acc,r)=>acc+(r.cost_minor??0n),0n); const returnsAmount=sumRevenue(returnRows); ... buildRow('totals','Итого', sales, returnsAmount, cogs, ...)`. buildRow (289-291): `revenue = sales - returnsAmount; grossProfit = revenue - cogs`. So revenue subtracts returns (sales−returns) but COGS is ONLY SUM(demand.cost_sum_minor) and never subtracts the returned goods' cost. SalesReturnPosition.costMinor (schema.prisma:5618, 'WEIGHTED-AVERAGE cost frozen at post-time ... re-enters inventory at carrying cost') is explicitly discarded as NULL. Same asymmetry in computeGroups (returnRows query lines 164-180 select only sum_minor; merge loop line 238-245 adds only `.returns`, never cogs).
  - repro: Post a Demand of 1,000,000 (cost 600,000), then a SalesReturn of that item (sale 1,000,000 / cost 600,000). P&L shows revenue = 1,000,000 − 1,000,000 = 0, but COGS stays 600,000 → grossProfit = 0 − 600,000 = −600,000 and the row renders red. The true gross profit on a fully-returned sale is 0 (zero-sum: inventory cost was reversed on the return). Every period containing returns understates gross/net profit by the returned goods' cost.
  - fix: Symmetrically reverse COGS on returns: join SalesReturnPosition to sum its costMinor per currency-bucket (it is already base, like demand cost_sum_minor) and subtract it from COGS. e.g. add `cogs -= returnCostMinor` where returnCostMinor = SUM(srp.cost_minor) for posted, non-deleted sales_returns in window, matching the existing weighted-avg freeze/reverse design. Mirror in both computeTotals and computeGroups.
- **[MED/date-tz/likely] dateTo collapses to UTC midnight → entire last selected day excluded (off-by-one period boundary)**
  - evidence: pnl.schema.ts:11 `dateTo: z.coerce.date()` turns the FE's date-only `2026-06-13` into `2026-06-13T00:00:00.000Z`. pnl.service.ts:79 (computeTotals window) and :158-159/:175-176/:192-193/:209-210 (computeGroups) all filter `AND moment <= ${filter.dateTo}`.
