## A. Structural / columns + i18n — 3 fixes

- **🔴 HIGH — dead search box → WIRED end-to-end.** `_search = useDebounce(searchInput,300)` was computed but **never threaded** into `params`/queryKey, and BE `SessionFilterSchema` had **no `search` field** — the rendered, typeable box silently filtered nothing (the `_`-prefix hid it from lint; sibling retail/sales threads `search` correctly). moysklad's «Смены» toolbar DOES show a search box, so the parity-correct fix is to **wire it**, not remove it. **Adversarial grounding:** the session `name` (moysklad «№») is **never populated** on `open()` (defaults to `''`), and our list links by **cashier**, so a moysklad-faithful "search by number" would hit an empty column. Wired BE `search` (trim·min(1)) → service `OR [{cashier.name contains}, {description contains}]` (mode insensitive); FE renamed `_search`→`search`, threaded into params + queryKey. Placeholder kept as «Имя кассира…» (honest — primary axis = cashier) → resolves the engine's *uncertain* placeholder finding (do NOT switch to «Номер или комментарий»: we have no number column). +2 BE schema tests.
- **MED — hardcoded Latin-uz state header `header: 'Holat'` → `tCommon('status')`.** Every other column header used `t(...)`; `'Holat'` (the literal uz value of `state`) leaked Uzbek into the RU locale — gate-blind (no-hardcoded gate is Cyrillic-only; it never scans list `page.tsx`). `common.status` already resolves ru «Статус» / uz «Holat» (0 new keys). The extra state Badge column itself is an accepted redesign (moysklad shows state via the filter chips); only the header label was the bug.
- **MED — fetched-but-unrendered «Склад» + «Организация» columns → ADDED.** BE `cashier-session.service.ts` list() include already fetches `store` AND `organization`, but the FE rendered neither (`organization` wasn't even on `SessionRow`). moysklad's clean PNG shows both as standard columns → the explicit L4/L5 fetched-but-unrendered carve-out (not a manufactured richer-column delta). Added both columns after `cash_desk` (moysklad order: Точка продаж → Склад → Организация) via existing `fields.store` («Склад») / `fields.organization` («Организация») keys (0 new keys); typed `organization` on `SessionRow`. **`cash_desk` «Касса» vs moysklad «Точка продаж» kept** (our entity is genuinely a CashDesk; mapping uncertain → DEFER).

## B. Interactive / money + wiring — 2 fixes

- **MED — money cells dropped the per-row «сум» suffix (list convention).** `sales` sum (`formatMoney(BigInt(salesSumMinor))`) + `discrepancy` (`formatMoney(d)`) rendered the suffix on every row, unlike ~35 sibling lists. Switched to `formatMoney(value, row.cashDesk.currency, { displayAs: 'none' })` — and threaded the **real `cashDesk.currency`** (already on the row) instead of defaulting to UZS.
- **LOW — CSV cellText emitted raw/partial values.** `sales` cellText returned only `String(salesCount)` (dropped the money); `discrepancy` cellText returned the raw minor-unit integer. Both now format via `formatMoney(..., {displayAs:'none'})` (keeps the count + money for `sales`, NaN-safe `—` for null discrepancy).
